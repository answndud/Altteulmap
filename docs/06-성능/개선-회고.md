# 성능 개선 회고

## 실제 변경

- 지도 query에 bbox validation, 결과 cap, latitude/longitude 중심 index를 적용했다.
- Worker DB client에 statement/lock/connect/response timeout baseline을 적용했다.
- DB unavailable을 mock fallback으로 숨기지 않고 빠르게 실패하도록 했다.
- Hyperdrive는 optional fallback 경로만 두고, 측정 trigger 전 도입을 보류했다.

## 판단

1인 운영과 낮은 초기 데이터 규모에서는 단일 Worker + PostgreSQL이 단순하다. Hyperdrive나 queue를 먼저 도입하면 운영 복잡도가 증가하므로 connection/latency evidence를 조건으로 남겼다.

## 한계

before/after의 동일 환경 원본 p50/p95/p99 세트가 모두 보존된 것은 아니다. 따라서 이 문서는 개선 방향과 historical evidence를 기록하며, 성능 향상률을 주장하지 않는다.
