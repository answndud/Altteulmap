# 개발 연대기

## 1. Next.js에서 Vite React + Worker로 전환

상황 → 기존 구조의 runtime/build 복잡도와 Cloudflare 경계가 커졌다.

→ 처음의 한계 또는 실패 → framework 경계와 실제 배포 산출물 계약이 어긋날 수 있었다.

→ 검토한 대안 → 기존 framework 유지, Vite SPA + Worker BFF로 단순화.

→ 선택 → Vite React, React Router, Hono Worker 단일 배포를 선택했다.

→ 실제 구현 → vite config, Worker alias/output sync, migration contract와 deploy check를 추가했다.

→ 검증 방법 → build, typecheck, local smoke, Vite contract, E2E를 실행했다.

→ 결과 → 브라우저와 Worker API를 하나의 배포 경계로 설명할 수 있게 됐다.

→ trade-off → SSR과 framework 제공 기능은 줄고, client fetch와 Worker 계약 책임이 커졌다.

→ 남은 한계 → 기존 문서의 권장 스택과 현재 구현이 달라 canonical 대조표가 필요하다.

## 2. 익명 쓰기와 데이터 정합성 hardening

상황 → 장소·가격·댓글·신고를 익명으로 허용하면서 actor와 abuse 경계가 필요했다.

→ 검토한 대안 → 완전 회원 전용, IP-only, signed visitor actor + Turnstile/rate limit.

→ 선택 → 진입 장벽을 낮추되 signed actor, body cap, validation, rate limit을 조합했다.

→ 실제 구현 → public-write actor와 각 public write route, 가격 unique/CAS/transaction, migration guard를 적용했다.

→ 검증 방법 → unit contract, local price concurrency, DB migration/seed, E2E를 실행했다.

→ 결과 → stale/duplicate 요청과 anonymous ownership을 코드 경계로 설명할 수 있다.

→ trade-off → cookie 기반 actor는 실명성이 아니며 공개 abuse와 IP proxy 경계는 운영 검증이 필요하다.

→ 남은 한계 → 장소 merge와 백업 복구는 아직 별도 운영 설계다.

## 3. 운영 연결을 보수적으로 유지

상황 → Worker에서 PostgreSQL connection과 외부 provider를 직접 다룬다.

→ 검토한 대안 → 즉시 Hyperdrive/queue/AI provider 도입, 현재 direct connection 유지.

→ 선택 → timeout·fail-closed·측정 trigger를 먼저 두고 Hyperdrive는 보류했다.

→ 실제 구현 → db client baseline, health, deploy check, migration preflight, optional Hyperdrive fallback을 유지했다.

→ 검증 방법 → remote read-only smoke와 map historical measure를 확인했다.

→ 결과 → 단순성은 유지하면서 과도한 확장을 미뤘다.

→ trade-off → 실제 공개 트래픽·connection churn 데이터가 부족하다.

→ 남은 한계 → provider sandbox와 backup/restore rehearsal이 필요하다.
