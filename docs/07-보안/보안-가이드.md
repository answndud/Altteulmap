# 보안 가이드

## 인증과 세션

credentials password는 hash 비교 경계를 사용하고, session은 AUTH_SECRET 기반 signed cookie다. OAuth는 state cookie와 signed state, provider callback, code 교환을 사용한다. cookie 속성은 auth/session 구현과 runtime header를 기준으로 한다. AUTH_SECRET 누락은 fail closed가 원칙이다.

## 권한과 ownership

admin 화면을 숨기는 것만으로 권한을 부여하지 않는다. admin routes가 session role을 재검증한다. 댓글 삭제와 북마크는 user/visitor ownership을 확인한다. 장소·가격·신고 mutation은 route와 repository에서 대상 id와 상태를 재확인한다.

## 익명 쓰기 방어

장소·가격·댓글·신고 route에는 body cap, Zod validation, Turnstile, visitor actor, rate limit이 연결된다. IP fallback은 proxy header 신뢰 경계가 있으므로 Cloudflare 배포 경로에서 실제 header 공급을 확인해야 한다. cookie 재발급, replay, 신고 폭탄, 링크 spam에 대한 공개 트래픽 검증은 남아 있다.

## 입력·출력

사용자 입력은 schema validation 후 저장한다. 댓글과 링크는 저장형 XSS와 spam을 고려해야 하며 CSP는 피해 범위를 낮추는 보조선이지 sanitization의 대체가 아니다. API 오류와 로그에 secret·provider token·password가 포함되지 않아야 한다.

## AI 경계

현재 저장된 moderation suggestion은 운영자 적용 전 상태다. 외부 모델에 사용자 입력을 전송하는 실제 provider route가 확인되지 않으므로 AI 자동 검수를 완료로 표현하지 않는다. 도입 시 prompt injection, 개인정보, output schema, 비용/queue flooding을 별도 threat model로 추가한다.

## secret과 dependency

운영 secret은 Wrangler/Cloudflare binding으로 관리하고 저장소에 기록하지 않는다. USE_MOCK_DATA와 bypass token은 production에서 fail closed인지 확인한다. npm audit의 React Router upstream advisory는 현재 미해결 범위로 기록하고 공개 fix를 재평가한다.
