# 0007. 장소 검색은 `ILIKE '%q%'` + pg_trgm GIN 부분 인덱스로 처리한다

상태: 채택 · 관련 코드: `src/worker/places/places-read-map-repository.ts`, `drizzle/0018_search_trigram_indexes.sql`

## 맥락
검색어는 장소 이름·상호·도로명 주소·지역·대표 가격 라벨·설명·메모 중 어디에 있어도 맞아야 한다. 짧은 한국어 부분 문자열(`김밥`, `세탁`)이 대부분이다. 1,000곳에서는 순차 스캔도 10ms대였지만 데이터가 늘면 `ILIKE '%q%'`가 전체 스캔이 된다.

## 결정
- 쿼리는 7개 컬럼의 `ILIKE '%q%'` OR 조건을 유지한다.
- `pg_trgm` 확장을 켜고 각 컬럼에 `gin_trgm_ops` 인덱스를 `WHERE status = 'active'` 부분 인덱스로 만든다(공개 검색은 active만 본다).

## 대안과 버린 이유
- **Postgres full-text(`tsvector`)**: 한국어 형태소 사전이 기본 제공되지 않고, 부분 문자열 일치가 안 된다.
- **외부 검색엔진(Meilisearch·Elasticsearch)**: 데이터 규모에 비해 운영 부담이 크다.
- **컬럼 하나로 합친 표현식 인덱스**: 인덱스는 1개로 줄지만 쿼리와 표현식을 정확히 맞춰야 하고 컬럼 추가 시 재생성이 필요하다.

## 결과와 한계
- 3글자 미만 검색어는 trigram을 만들 수 없어 인덱스가 거의 도움이 안 된다(2글자 한국어 검색이 흔하다).
- 쓰기마다 GIN 인덱스 7개가 갱신된다. 쓰기가 적은 서비스라 감수한다.
- 관련도 순위는 없다. 정렬은 거리·가격 기준이다.
