# 기술 요구사항: 현재 구현 기준

## 시스템 경계

React 19 + Vite SPA가 브라우저 UI를 담당하고, Hono 기반 Cloudflare Worker가 /api BFF와 정적 asset 응답을 담당한다. Worker는 Drizzle ORM과 postgres driver로 PostgreSQL/Supabase에 접근한다. src/worker/db.ts는 optional Hyperdrive connection string을 우선하고 없으면 DATABASE_URL을 사용한다. 현재 wrangler.jsonc에는 Hyperdrive binding이 없다.

## 책임 분리

- src/client: route, form, map, query state, 접근성 UI
- src/worker/routes: HTTP contract, validation, actor/session 확인, response
- src/worker/*-repository.ts: SQL/Drizzle 조회·mutation과 transaction
- src/db: schema, enum, migration 대상 모델, seed
- scripts: migration preflight, import, smoke, 성능 측정, deploy check
- tests/unit, tests/e2e: 순수 helper/HTTP contract와 브라우저 흐름

클라이언트는 DB에 직접 연결하지 않는다. 공개 읽기와 쓰기 모두 Worker API를 경유한다.

## 인증·세션·권한

credentials와 Kakao/Naver OAuth route가 signed session cookie를 발급한다. cookie에는 HttpOnly, Secure, SameSite 및 만료 정책이 적용된다. OAuth callback은 signed state와 cookie state를 대조한 뒤 code를 provider token/profile로 교환한다. admin route는 UI 숨김이 아니라 서버에서 role을 다시 확인한다.

익명 쓰기는 visitor cookie actor와 rate limit/Turnstile을 결합한다. visitor actor는 서명된 값으로 위조를 어렵게 하지만, 실제 provider와 공개 트래픽 환경의 abuse 저항성은 별도 운영 검증이 필요하다.

## 데이터·transaction

가격 검증, report 처리, admin CAS 등 정합성이 중요한 mutation은 transaction과 조건부 update를 사용한다. 가격 원본 제보와 현재 대표 가격/이력은 서로 다른 역할을 갖는다. schema의 unique/check/index와 migration contract가 애플리케이션 invariant를 보완한다.

현재 비동기 event queue나 message broker는 없다. moderation suggestion은 저장된 제안과 운영자 최종 판단의 경계이며, 자동 공개를 의미하지 않는다.

## 성능·보안 기준

- 지도 조회는 bbox와 category/filter를 사용하고 결과 상한을 둔다.
- DB client에는 connect/statement/lock/response timeout baseline이 있다.
- API 응답에는 CSP 외 보안 header가 적용된다.
- public write는 body cap, validation, Turnstile, rate limit을 적용한다.
- 성능 수치는 시나리오 스크립트와 E2E performance 결과를 따로 기록한다. p95 목표가 실제 운영 SLO라는 뜻은 아니다.

## 실행과 검증

Node.js 최소 버전은 package.json의 engines에 정의된 >=20.19.0이다. 기본 검증은 npm run verify, 품질 검증은 npm run verify:quality, build/deploy 산출물은 npm run cf:build:vite, npm run deploy:check:vite로 확인한다. DB/E2E 명령은 disposable local PostgreSQL에서만 수행한다.

## 목표와 현재의 차이

기존 TRD의 Hyperdrive, Sentry, Resend, PostGIS, SWR/TanStack Query는 일부가 권장안 또는 미래 선택지다. 현재 구현 여부는 [대조표](../05-기능-대조/대조표.md)에서 확인하며, 문서의 “권장”을 “운영 완료”로 해석하지 않는다.

## 기술 요구사항의 수용 기준

| 경계 | 수용 기준 | 관찰 지점 |
| --- | --- | --- |
| HTTP 입력 | body 256 KiB 이하, Zod parse 성공, path/query 범위 유효 | src/worker/index.ts, 각 route schema |
| 인증/권한 | session signature·expiry 검증, admin role 서버 재검증 | src/worker/auth/session.ts, admin-support.ts |
| 공개 쓰기 | actor 결정 → persistent rate limit → Turnstile → pending 저장 | public-write-support.ts, public-write-* routes |
| 가격 반영 | pending report만 moderation transaction에서 accepted/rejected, distinct actor count로 verified | admin-price-review-repository.ts |
| DB 장애 | mock으로 숨기지 않고 503/no-store/requestId로 관찰 | src/worker/index.ts, db.ts, health.ts |
| 배포 | Node version, build output, migration drift, whitespace를 CI에서 확인 | package.json, .github/workflows/ci.yml |

## 의도적인 계약 미사용

별도 OpenAPI 생성, client/server 자동 타입 공유, queue/message broker, distributed cache는 현재 없다. 따라서 API 계약은 route schema와 테스트, 문서 대조로 관리하며, 규모가 커질 때 도입 비용과 이점을 다시 판단한다.
