# 테스트 전략 감사 및 개선 보고서 — 2026-08-25

## 감사 목적

라인 수가 아니라 실제 운영 회귀를 잡는 것을 목표로 기존 단위·E2E 테스트와 인증, 권한, 공개 쓰기, 관리자 검수, DB 정합성, 장애 처리 경계를 대조했다. 동일 동작을 여러 계층에서 반복하지 않고, 경계와 사용자 결과를 함께 확인하는 테스트를 우선했다.

## 이번 개선

### `다른 방문자는 코멘트를 삭제할 수 없다`

- 보호하는 실제 실패: 삭제 요청자가 임의의 댓글 ID와 자신의 쿠키만으로 타인의 댓글을 삭제하는 IDOR/BOLA 회귀.
- 검증 방식: 댓글을 한 브라우저 컨텍스트에서 만들고, 별도 컨텍스트에서 삭제 API를 호출해 403과 원본 보존을 확인한다.
- 중복 회피: 소유권 비교를 구현 함수 단위로 복제하지 않고 세션·쿠키·라우트·저장소 경계를 함께 통과시킨다.

### `댓글 저장 서버 오류에서도 입력 내용을 유지한다`

- 보호하는 실제 실패: 503 응답 뒤 폼이 성공처럼 비워지거나 사용자가 작성한 내용을 잃어 재입력해야 하는 장애.
- 검증 방식: API를 결정적인 503 JSON 응답으로 대체하고 사용자 오류 문구와 입력값 보존을 확인한다.
- 중복 회피: 네트워크 스택 자체를 재현하지 않고 프론트엔드의 HTTP 오류 생명주기만 검증한다.

## 기존 테스트 전략 평가

- 단위 테스트는 인증 세션, CSRF, OAuth state, 방문자 서명, 본문 제한, 요청 제한, 지도 파생 로직을 결정적으로 보호한다.
- E2E는 지도 탐색, 가입·로그인, 공개 제보, 관리자 승인·반려, 댓글, 신고, 북마크와 접근성을 보호한다.
- DB에 의존하는 가격 동시성·마이그레이션·프로덕션 검사는 별도 스모크/통합 명령으로 분리되어 있어 단위 테스트에 과도하게 모의하지 않는다.
- 임의 sleep, 통제되지 않은 네트워크·시간·난수, 비공개 구현 세부사항 검증은 새 테스트에 추가하지 않았다.

## 남은 미검증 위험

- 실제 OAuth 제공자에서 code replay/PKCE, 제공자 장애와 잘못된 프로필의 원격 동작.
- 두 관리자 세션의 동시 장소·신고 결정과 production DB에서의 migration replay.
- 실제 DB/Hyperdrive 연결 고갈, 프로세스 재시작·배포 중단, 외부 Turnstile/Naver SDK 장애.
- 북마크의 다중 Worker 격리·재시작 후 영속성 및 가격 제보의 실제 중복 요청 경합.
- 대용량 지도 검색의 p95, 메모리·연결 사용량, 운영 트래픽 기준 요청 제한 저장소 장애.

## P2·P3 추가 보호 대상

- authorization 통합 테스트는 인증 없음 401, 일반 사용자 관리자 API 403, DB role 강등 후 세션 거부, 사용자별 bookmark 격리를 실제 PostgreSQL과 Worker route에서 확인한다.
- 가격 제보 재전송과 bookmark 동시 설정은 unique constraint와 submission key가 중복 행을 만들지 않는지 확인한다.
- 장소 등록 503은 입력 보존과 접근 가능한 `alert` 상태 메시지를 확인하고, 데스크톱 Chromium·axe 검사는 기존 핵심 여정을 유지한다.
- 검색 benchmark와 DB contract check는 성능·schema·timeout 조건이 CI에서 재현되는지 확인한다.
