# 배포 절차

## 사전 확인

1. migration이 필요한지 확인한다.
2. npm run lint와 npm run typecheck를 실행한다.
3. npm run cf:build:vite와 npm run deploy:check:vite를 실행한다.
4. production DB에는 db push를 사용하지 않는다.

## migration 포함 배포

운영 DB migration을 code deploy보다 먼저 적용한다. scripts/migrate-production.mjs의 production guard, migration history, schema check를 확인한다. 명령은 운영 승인과 별도 backup 정책이 있는 경우에만 실행한다.

## Worker 배포

npm run deploy가 build와 wrangler deploy를 실행한다. 배포 후 SMOKE_PUBLIC_URL을 지정한 npm run smoke:remote를 read-only 범위로 실행한다. 실제 admin mutation QA는 이 smoke로 대체하지 않는다.

## 원격 인증 smoke

`SMOKE_ADMIN_EMAIL`과 `SMOKE_ADMIN_PASSWORD`를 지정하면 CSRF 토큰 발급, 관리자 credentials 로그인, session role, 관리자 API 접근, signout과 session 폐기를 확인한다. `SMOKE_USER_EMAIL`과 `SMOKE_USER_PASSWORD`도 함께 지정하면 일반 사용자 session이 관리자 API에서 `403/FORBIDDEN`을 받는 권한 경계를 추가로 확인한다. 두 일반 사용자 secret 중 하나만 지정하면 smoke가 실패한다.

OAuth smoke는 Kakao/Naver authorization redirect와 state cookie 속성을 확인하고, synthetic code/state callback이 외부 token 교환 없이 `/login?error=OAuthCallback`으로 거부되는지 확인한다. 실제 provider 동의·callback 성공은 provider sandbox에서 별도 수행해야 한다.

## 현재 미검증

이 문서는 배포 명령을 정의하지만, 모든 secret 조합·OAuth provider·실제 트래픽·DB 복구를 매 배포마다 검증했다는 뜻이 아니다.
