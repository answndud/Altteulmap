# 백업·복구

## 현재 상태

운영 DB가 Supabase PostgreSQL이라는 설정과 migration/seed 절차는 있으나, 이 저장소에서 실제 백업 생성·보존·disposable restore를 실행한 증거는 없다. 따라서 복구 가능성을 완료된 운영 역량으로 말하지 않는다.

## 필요한 절차 초안

1. 백업 시각, schema/migration version, 보존 기간을 기록한다.
2. production과 분리된 disposable PostgreSQL에 복구한다.
3. migration check, row count, 핵심 invariant, read-only smoke를 확인한다.
4. 복구 결과와 실패한 constraint를 기록한다.

복구가 검증되기 전에는 destructive migration과 import를 운영 승인 없이 실행하지 않는다.
