# 롤백

## 코드 배포 롤백

1. 이전 Worker deployment id와 현재 migration version을 확인한다.
2. 현재 schema를 사용하는 코드인지 먼저 판정한다. schema가 확장된 경우 이전 코드가 새 nullable/추가 컬럼을 안전하게 무시하는지 확인한다.
3. 호환되지 않는 migration이면 code-only rollback을 중단하고 forward-fix 또는 승인된 데이터 복구를 선택한다.
4. 이전 Worker를 배포한 뒤 `/api/health?deep=1`, 공개 map/detail read-only smoke, migration 상태를 확인한다.

## 데이터 변경 롤백

장소 merge, import, admin bulk mutation은 dry-run·audit log·원본 보존·복구 방법이 없으면 실행하지 않는다. 백업 복구는 production과 분리된 restore DB에서 먼저 수행하고, 실제 production 복원은 장애 책임자의 승인과 RPO/RTO 기록 뒤 진행한다.

## 배포 중단 판정

- migration 전제조건 실패, schema drift, backup 증적 부재, restore 검증 실패는 배포를 중단한다.
- Worker 배포 실패는 이전 deployment로 되돌리되 이미 적용된 migration은 자동 rollback하지 않는다.
- 5xx, DB unavailable, OAuth callback 오류가 증가하면 반복 mutation을 중단하고 requestId·배포 id·migration version을 장애 기록에 남긴다.

## 검증 명령

```bash
npm run db:check:production
SMOKE_PUBLIC_URL="https://staging.example" npm run smoke:remote
```

실제 rollback rehearsal은 staging에서 이전 Worker와 현재 schema 조합을 검증한 `evidence.json`이 있을 때만 완료로 표시한다.
