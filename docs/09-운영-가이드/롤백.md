# 롤백

## 코드 롤백

이전 Worker 배포 버전을 확인하고, 현재 코드와 DB migration의 호환성을 먼저 판단한다. code deploy만 되돌려도 이미 적용된 schema가 자동으로 되돌아가지 않으므로 migration rollback과 code rollback을 별도 결정한다.

## 데이터 변경

장소 merge, import, admin bulk mutation은 원본 보존·dry-run·audit log·복구 방법이 없으면 실행하지 않는다. 현재 장소 merge mutation의 운영 rollback은 미구현이다.

## 검증

롤백 후 /api/health, 공개 map/detail read-only smoke, migration check를 실행한다. 실제 rollback rehearsal은 미검증이다.
