# AltteulMap Impeccable Context

## Required Design Context
- Target audience: Korea-based users who need to reduce everyday spending, especially students, first-job workers, people living alone, lunch-time office workers, and households comparing nearby essential services.
- Primary use cases: find a cheap meal or service nearby before making a quick offline decision; compare representative prices on a map; contribute a place or price report so the map stays useful.
- Brand personality: practical, trustworthy, clear, local, price-aware, warm, and grounded.

## Product Direction
- AltteulMap is a map-first utility product, not a marketing site.
- The first screen should immediately communicate "useful price map".
- Representative price, verification status, update recency, category, and district are primary UI signals.
- The product should feel like a credible local service that people can reopen before lunch, errands, laundry, pharmacy trips, printing, or groceries.

## Aesthetic Direction
- Direction: warm utilitarian local-price map.
- Visual memory: price-led place cards over a dominant map, with restrained warm materials and trustworthy verification cues.
- Use warmth through tinted neutrals, material contrast, and Korean product copy rather than decorative illustration or beige-on-beige softness.
- Keep the interface dense enough for comparison but calm enough for outdoor mobile use.

## System Constraints
- Stack: Next.js App Router, React, TypeScript, Tailwind CSS, Naver Maps, Cloudflare Workers/OpenNext.
- Mobile-first web product with safe-area padding and 44px minimum touch targets.
- Avoid Node-only runtime assumptions in app code because production runs on Cloudflare Workers.
- Use repo-local AI workflow only. Do not write global `~/.codex`, `~/.claude`, or other user-level agent configuration.

## Existing Product Sources
- This file is the canonical local design context for Codex App and Impeccable skills.
- `docs/product/prd.md` and `docs/product/trd.md` define product goals and technical constraints.
- When a design decision is ambiguous, prefer the product constraints in `prd.md`/`trd.md` and document the decision in the active project docs.

## Core UI Rules
- Map first: the homepage and `/map`-like exploration flow must keep the map dominant.
- Price first: price is the strongest repeated element in cards, list rows, pins, and detail sheets.
- Trust before charm: show verification, update recency, and source context clearly.
- One surface depth at a time: avoid nested cards and unnecessary wrappers.
- Mobile is not compressed desktop: use bottom sheets, compact filters, safe areas, and clear dismissal.
- Use explicit state changes for filters: background, border, text, and removable active tokens.

## Typography
- Application UI uses fixed type scales, not viewport-fluid typography.
- Current recommended families: `IBM Plex Sans KR` for UI and `IBM Plex Mono` or tabular numerals for prices/counts.
- Price numerals should use tabular treatment and enough weight to anchor scanning.
- Avoid a crowd of adjacent sizes; prefer fewer sizes with stronger hierarchy.

## Color
- Use tinted neutrals, not pure grayscale.
- Existing product tokens remain the starting point:
  - canvas `#f4f1ec`
  - surface `#fffdf9`
  - subtle `#f0ebe4`
  - text strong `#171411`
  - accent `#b55a2b`
- Semantic colors should be grounded: deep jade, baked amber, muted brick red, steel blue.
- Do not use purple/blue AI gradients, gradient text, decorative dark glows, or gray text on tinted backgrounds.

## Layout
- Desktop exploration target: map/list split with map as the dominant 8-column area and list/detail as the supporting 4-column rail.
- Mobile exploration target: compact header/search/filter, map in first viewport, list/detail as bottom sheets.
- Use a 4pt spacing scale and `gap` for sibling relationships.
- Use container-aware cards and list cells where practical.

## Copy
- Korean copy should be direct, product-like, and practical.
- Prefer action plus object labels, such as `장소 등록`, `가격 추가`, `이 지역 다시 찾기`, `가격 보기`.
- Avoid vague labels like `상세`, `확인`, `제출`, `완료` when a more specific action exists.

## Anti-Patterns To Reject
- Marketing landing pages before the map.
- Hero prose that delays the actual product.
- Cards inside cards.
- Flat 18-category chip walls.
- Duplicate CTA clusters in header and page body.
- Beige-on-beige low contrast.
- Decorative gradients used as hierarchy.
- Mixing overview clusters and individual place markers in the same marker mode.
