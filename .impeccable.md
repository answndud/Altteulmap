# AltteulMap Impeccable Context

## Required Design Context
- Target audience: Korea-based users who need to reduce everyday spending, especially students, first-job workers, people living alone, lunch-time office workers, and households comparing nearby essential services.
- Primary use cases: find a cheap meal or service nearby before making a quick offline decision; compare representative prices on a map; contribute a place or price report so the map stays useful.
- Brand personality: practical, trustworthy, clear, local, price-aware, warm, and grounded.

## Product Direction
- AltteulMap is a map-first utility product, not a marketing site.
- The first screen should immediately communicate "useful price map".
- Representative price, verification status, update recency, category, and district are primary UI signals.
- The product should feel like a credible local service that people can reopen before lunch, errands, laundry, pharmacy trips, printing, or groceries.

## Aesthetic Direction
- Direction: clear, square, price-first utility map. Cool neutral surfaces with one blue primary for actions and a warm orange accent reserved for price and emphasis.
- Visual memory: price-led place cards over a dominant map, with trustworthy verification cues.
- Source of truth: the CSS variables at the top of `src/client/styles.css` (`--altteul-*`). This document describes the direction; when a color value changes, change the tokens, not this file.
- All corners are square on purpose (`border-radius: 0` is enforced globally); do not reintroduce rounded surfaces.
- Keep the interface dense enough for comparison but calm enough for outdoor use.

## System Constraints
- Stack: Vite, React Router, React, TypeScript, Tailwind CSS, Naver Maps, Cloudflare Workers.
- Desktop web is the quality target (see `PLAN.md` Goal). Mobile layouts exist but are not verified or a design goal.
- Avoid Node-only runtime assumptions in app/worker code because production runs on Cloudflare Workers.
- Use repo-local AI workflow only. Do not write global `~/.codex`, `~/.claude`, or other user-level agent configuration.

## Core UI Rules
- Map first: the homepage and `/map`-like exploration flow must keep the map dominant.
- Price first: price is the strongest repeated element in cards, list rows, pins, and detail sheets.
- Trust before charm: show verification, update recency, and source context clearly.
- One surface depth at a time: avoid nested cards and unnecessary wrappers.
- Where mobile layouts exist, keep them separate from desktop (bottom sheets, compact filters, clear dismissal) rather than compressing the desktop layout.
- Use explicit state changes for filters: background, border, text, and removable active tokens.

## Typography
- Application UI uses a fixed five-step scale, not viewport-fluid typography: 12px (`text-xs`), 14px (`text-sm`), 16px (`text-base`), 24px (`text-2xl`), 40px (`text-[2.5rem]`, price and page titles).
- Do not add new sizes or arbitrary pixel values such as `text-[11px]`; pick the nearest step.
- Families: `IBM Plex Sans KR` for UI; prices and counts use tabular numerals (`altteulmap-price-number`).
- Prefer fewer sizes with stronger hierarchy.

## Color
- Use tinted neutrals (hue 255), not pure grayscale. Tokens live in `src/client/styles.css`:
  - canvas `--altteul-bg-canvas`, surface `--altteul-bg-surface`, subtle `--altteul-bg-subtle`
  - text `--altteul-text-strong|primary|secondary|tertiary`
  - primary (blue) `--altteul-primary*`, accent (orange) `--altteul-accent*`
- Semantic colors: success/warning/info/danger tokens with soft, border, and text variants.
- Do not use purple/blue AI gradients, gradient text, decorative dark glows, or gray text on tinted backgrounds. Text on a filled chip must be checked against the cascade (white-on-white bugs have happened with `.altteulmap-chip` and `.altteulmap-accent-chip`).

## Layout
- Desktop exploration target: the map takes at least ~70% of the first 1440x900 viewport; the list/detail rail overlays the map at 26rem (30rem on 2xl) instead of pushing it down. The category filter opens as a popover and never moves the map.
- Mobile exploration target: compact header/search/filter, map in first viewport, list/detail as bottom sheets.
- Use a 4pt spacing scale and `gap` for sibling relationships.
- Use container-aware cards and list cells where practical.

## Copy
- Korean copy should be direct, product-like, and practical.
- Prefer action plus object labels, such as `장소 등록`, `가격 추가`, `이 지역 다시 찾기`, `가격 보기`.
- Avoid vague labels like `상세`, `확인`, `제출`, `완료` when a more specific action exists.

## Anti-Patterns To Reject
- Marketing landing pages before the map.
- Hero prose that delays the actual product.
- Cards inside cards.
- Flat 18-category chip walls.
- Duplicate CTA clusters in header and page body.
- Beige-on-beige low contrast.
- Decorative gradients used as hierarchy.
- Mixing overview clusters and individual place markers in the same marker mode.
